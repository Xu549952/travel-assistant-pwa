三、本地测试操作步骤

方法 A：使用一键脚本（推荐）

1

打开 PowerShell 终端

按 Win + X，选择"Windows PowerShell"或"终端"。确保在项目目录下：

cd d:\项目1
2

安装依赖（首次运行需要，后续可跳过）

npm install

这一步会安装 @lhci/cli、lighthouse 和 http-server。已执行过，无需重复。

3

运行完整测试

.\lhci-local.ps1 autorun

脚本会自动：

1. 检测 Edge 浏览器路径并设置 CHROME_PATH 环境变量

2. 启动本地 HTTP 服务器 (端口 8080)

3. 运行 Lighthouse 测试 3 次（取中位数）

4. 执行阈值断言（Performance ≥ 85 为 error，Accessibility ≥ 90 为 error）

5. 生成 HTML 报告到 .lighthouseci/ 目录

4

查看测试报告

测试完成后，在浏览器中打开生成的 HTML 报告：

# 方式 1：在 Edge 中直接打开
start msedge "d:\项目1\.lighthouseci\lighthouse-report.html"

# 方式 2：通过 LHCI 服务器查看历史报告
.\lhci-local.ps1 status
# 然后访问 http://localhost:9001

方法 B：手动分步操作

1

设置浏览器路径

$env:CHROME_PATH = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
2

启动本地服务器（新终端窗口）

cd d:\项目1
npx http-server . -p 8080 --cors -c-1

看到 Starting up http-server 表示服务器已启动。保持此窗口不要关闭。

3

运行 Lighthouse（另一个终端窗口）

cd d:\项目1
npx lhci autorun

或者直接用 lighthouse 命令（更灵活）：

# 仅测试 accessibility（快速，约 10 秒）
npx lighthouse "http://localhost:8080/旅行助手.html" --only-categories=accessibility --preset=desktop --chrome-flags="--no-sandbox --headless" --max-wait-for-load=15000 --output=html --output-path=".lighthouseci/report.html"

# 测试全部类别（较慢，约 1-2 分钟）
npx lighthouse "http://localhost:8080/旅行助手.html" --preset=desktop --chrome-flags="--no-sandbox --headless" --max-wait-for-load=45000 --output=html --output-path=".lighthouseci/report.html"
4

执行阈值断言

npx lhci assert

此命令会根据 lighthouserc.json 中的阈值检查测试结果。

其他可用命令

命令用途
.\lhci-local.ps1 serve仅启动服务器，手动在浏览器中查看页面
.\lhci-local.ps1 collect仅收集 Lighthouse 数据，不执行断言
.\lhci-local.ps1 assert仅执行断言（需先 collect）
.\lhci-local.ps1 status启动 LHCI 报告查看服务器 (端口 9001)
.\lhci-local.ps1 help查看帮助信息

类别得分阈值状态

关键性能指标

指标值说明
First Contentful Paint (FCP)4.5s首次内容绘制 - 页面首次显示内容的时间
Largest Contentful Paint (LCP)4.5s最大内容绘制 - 最大元素完成渲染的时间
Total Blocking Time (TBT)0ms总阻塞时间 - 主线程被阻塞的总时间
Cumulative Layout Shift (CLS)0累积布局偏移 - 页面视觉稳定性
Speed Index4.5s速度指数 - 页面内容填充速度

Performance 59 分 - 问题分析

性能得分低于 85 分阈值，主要原因是：

1. CDN 资源加载缓慢 (FCP/LCP = 4.5s)

页面加载了 6+ 个 CDN 脚本（Leaflet、jsPDF、html2canvas、marked、mammoth、DOMPurify），这些渲染阻塞资源导致首次绘制延迟。

2. TBT = 0ms 和 CLS = 0 表现优秀

说明页面 JavaScript 执行效率高，且没有布局偏移问题。

Accessibility 100 分 - 优秀

无障碍评分满分，所有关键审计项均通过：

颜色对比度、文档标题、HTML lang 属性、meta viewport、标题层级、按钮命名、landmark 标记等。

注意: 由于 Performance (59) < 阈值 (85)，LHCI autorun 会以非零退出码结束（CI 失败）。这是预期行为，提示需要优化性能。PWA (29) 仅为 warn 级别，不会导致 CI 失败。

# 2. 仓库名: travel-assistant (或自定义)
# 3. 选择 Public 或 Private
# 4. 不要勾选 "Add a README" (已有)

1

在 GitHub 仓库页面点击 Actions 标签页查看运行状态。

在 Actions 运行详情页 → Artifacts 区域 → 下载 lighthouse-reports

3

也可以在 Actions 页面手动触发测试：

选择 Lighthouse CI 工作流 → 点击 Run workflow 按钮

六、评分阈值说明

阈值配置在 lighthouserc.json 的 assert.assertions 中：

审计项阈值级别含义
categories:performance≥ 85error不通过则 CI 失败
categories:accessibility≥ 90error不通过则 CI 失败
categories:best-practices≥ 80warn仅警告，CI 不失败
categories:seo≥ 80warn仅警告，CI 不失败
categories:pwa≥ 70warn仅警告，CI 不失败
csp-xss= 1warnCSP 安全检查
uses-text-compression= 1warn文本压缩检查
render-blocking-resources≥ 0.9warn渲染阻塞资源
unused-javascript≥ 0.8warn未使用的 JavaScript
如何调整阈值: 编辑 lighthouserc.json，修改 minScore 值（0-1 之间，0.85 = 85 分）。将 "error" 改为 "warn" 可降级为警告。

七、常见问题与排查

问题 1：测试运行很长时间不结束

原因: 旅行助手页面加载了多个 CDN 脚本（Leaflet、jsPDF 等），并持续调用天气 API 和地图瓦片，Lighthouse 需要等待页面达到"网络安静"状态。

解决方案:

1. 配置中已设置 maxWaitForLoad: 45000（45 秒上限），Lighthouse 会在超时后强制继续

2. 如需快速测试，可仅测试 accessibility 类别（约 10 秒完成）：

npx lighthouse "http://localhost:8080/旅行助手.html" --only-categories=accessibility --preset=desktop --chrome-flags="--no-sandbox --headless" --max-wait-for-load=15000 --output=html --output-path=".lighthouseci/report.html"

问题 2：CHROME_INTERSTITIAL_ERROR

原因: 本地 HTTP 服务器未运行或已停止，Edge 无法访问页面。

解决方案:

1. 确保服务器正在运行：

# 检查端口 8080
Test-NetConnection -ComputerName localhost -Port 8080

# 如果不可连接，重启服务器
.\lhci-local.ps1 serve

2. 使用 .\lhci-local.ps1 autorun 时，LHCI 会自动管理服务器启停

问题 3：git 命令未找到

原因: Git 未添加到系统 PATH。

解决方案:

$env:PATH = 'C:\Program Files\Git\cmd;' + $env:PATH

或永久添加：在系统环境变量中添加 C:\Program Files\Git\cmd

问题 4：Performance 得分低（59/100）

主要瓶颈: 6 个 CDN 脚本导致 FCP/LCP = 4.5 秒。

优化建议:

1. 延迟加载非关键脚本 - 将 mammoth.js、jspdf、html2canvas 等改为按需加载

2. 添加 resource hints - 对 CDN 域名使用 dns-prefetch 或 preconnect

3. 合并 CDN 脚本 - 使用打包工具将多个脚本合并为一个

4. 降低阈值 - 如果暂时无法优化，可将 Performance 阈值从 85 降至 60：

"categories:performance": ["error", { "minScore": 0.6 }]

问题 5：PWA 得分低（29/100）

原因: 单文件 HTML 架构的 PWA 支持受限。

主要扣分项: manifest.json 通过 Blob URL 动态生成（部分审计项无法检测），Service Worker 注册路径问题。

说明: PWA 仅为 warn 级别，不会导致 CI 失败。如需提升，需将 manifest.json 提取为独立文件。
